# Entropy — Homebrew tap

Постоянный Homebrew tap `D19ital/entropy` для конфигуратора клавиатур Ergohaven. Это отдельный канал установки, поддерживаемый в аккаунте D19ital, не репозиторий организации Ergohaven и не Homebrew/homebrew-cask.

Cask `entropy` скачивает **официальные DMG из ergohaven/entropy**, не пересобирает и не переподписывает приложение. Версия закреплена в определении cask; SHA256 заданы отдельно для Apple Silicon и Intel. Сейчас опубликована версия **0.4.0**.

## Установка

Нужен установленный [Homebrew](https://brew.sh/). Полностью закройте другие копии Entropy перед запуском установленной версии. Перед заменой рабочей версии экспортируйте важные настройки и раскладки и сохраните рабочее приложение. Не запускайте старую и новую версии одновременно.

Если `/Applications/Entropy.app` уже существует, сначала разберитесь, какая это версия и как она установлена. Не применяйте `--force`, `--adopt` или ручное удаление рабочей копии ради прохождения установки.

В Terminal выполните команды из блока. Отдельно вводить `sh` не нужно:

```
brew tap D19ital/entropy &&
brew install --cask D19ital/entropy/entropy
```

Для отдельной папки приложений вместо второй команды можно использовать:

```
brew install --cask --appdir "$HOME/Applications/Entropy-Homebrew" D19ital/entropy/entropy
```

У отдельной папки приложения **общие с другими копиями Entropy пользовательские настройки и macOS-разрешения**. Это не изоляция данных.

## Первое разрешение macOS

Текущие DMG не имеют цепочки Developer ID + notarization. Обычная установка через Homebrew не заменяет эту проверку; первое открытие может быть заблокировано Gatekeeper.

Если вы доверяете этому источнику и видите предупреждение, что Apple не удалось проверить приложение:
1. Нажмите «Готово», не «Переместить в Корзину».
2. Откройте **Системные настройки → Конфиденциальность и безопасность → Безопасность**.
3. Для Entropy нажмите **«Открыть всё равно»**, подтвердите действие системным способом и откройте приложение.

Это пользовательское исключение для конкретного приложения, а не отключение Gatekeeper целиком. Если кнопки нет, повторите попытку открытия именно установленной копии и снова откройте настройки. При сообщении об обнаруженном вредоносном ПО или повреждении приложения остановитесь; не пытайтесь обойти это предупреждение.

Не нужны `xattr`, `--no-quarantine`, отключение Gatekeeper или скрипты снятия quarantine. Пароль следует вводить только в системных окнах Mac.

[Официальная инструкция Apple](https://support.apple.com/ru-ru/102445).

## Обновление

Полностью выйдите из Entropy через **⌘Q**, затем:

```
brew update &&
brew upgrade --cask D19ital/entropy/entropy
```

Если при установке выбрана отдельная папка, сохраняйте её и при обновлении:

```
brew update &&
brew upgrade --cask --appdir "$HOME/Applications/Entropy-Homebrew" D19ital/entropy/entropy
```

`brew update` обновляет описание доступной версии, `brew upgrade` — само приложение. Пока cask содержит ту же версию, обновления не будет. Встроенный обновлятор Entropy в этом сценарии не используется.

Новые официальные релизы становятся доступны через tap после обновления его сопровождающим; автоматического переноса каждого GitHub-релиза в cask пока нет.

## Что уже проверено, а что не гарантируется

На одном Mac с Apple Silicon и Homebrew 7.0.9 проверен **локальный тестовый cask**, использовавший те же официальные DMG:
- установка 0.3.20 через Homebrew — успешно;
- запуск 0.3.20 после одного «Открыть всё равно», затем повторный запуск — успешно;
- настоящий `brew upgrade` 0.3.20 → 0.4.0 с сохранением пути — успешно;
- первый и повторный запуск 0.4.0 без нового «Открыть всё равно» — успешно;
- `spctl --assess` при этом возвращал `rejected`: стандартное доверие Gatekeeper не появилось;
- Homebrew предупредил о смене подписанта, но в этом тесте повторного разрешения не потребовалось.

Тест был с токеном `entropy-brew-test`, не с новым публичным `D19ital/entropy/entropy`. Переход между этими cask — отдельная операция, **не проверка обновления версии**.

Это не гарантия отсутствия запросов для всех будущих версий, других Mac, другого пути или чистой учётной записи. Удаление cask не сбрасывает прежние разрешения macOS. Сохранение Accessibility/Input Monitoring и запуск Intel-версии на Intel Mac отдельно не проверены; целостность обоих DMG проверена по SHA256.

## Переход с тестового cask

Если установлен `entropy-brew-test`, сначала посмотрите его путь:

```
brew list --cask entropy-brew-test
```

Закройте приложение, экспортируйте нужные настройки и сохраните рабочую копию **вне пути, указанного этой командой**, если она нужна для отката. Затем:

```
brew uninstall --cask entropy-brew-test &&
brew tap D19ital/entropy &&
brew install --cask D19ital/entropy/entropy
```

Не добавляйте `--zap` или `--force`. Обычное удаление старого тестового cask удаляет установленный им app; пользовательские настройки этим рецептом не очищаются. Если новая установка сообщает о конфликте с существующей `Entropy.app`, остановитесь, а не удаляйте её автоматически. Для сосуществования с рабочей копией используйте отдельную папку из раздела установки. После перехода запрос macOS может появиться вновь — это проверяется, а не обещается заранее.

Локальный tap `local/entropy-test` не нужно удалять ради установки постоянного tap. Не меняйте вручную файлы нового tap для обновления версии.

## Диагностика

Список файлов Homebrew показывает фактический путь установки:

```
brew list --cask D19ital/entropy/entropy
brew info --cask D19ital/entropy/entropy
```

Для стандартной установки версия и оценка Gatekeeper проверяются так:

```
APP="/Applications/Entropy.app"
if [ -f "$APP/Contents/Info.plist" ]; then
  /usr/libexec/PlistBuddy -c 'Print :CFBundleShortVersionString' "$APP/Contents/Info.plist"
  spctl --assess --type execute --verbose=4 "$APP"
else
  printf 'Проверьте фактический путь приложения через brew list.
'
fi
```

Для отдельной папки замените `APP` фактическим путём. `rejected` и возможность запуска после пользовательского исключения — разные результаты; сообщение само по себе не показывает, открылось ли окно приложения.

## Проверки tap и сопровождение

CI на macOS загружает определение cask через Homebrew, проверяет Ruby-синтаксис/контракт архитектур и стиль cask, скачивает DMG с проверкой SHA256. Он не открывает приложение, не выдаёт macOS-разрешения и не проверяет обновление на пользовательском Mac.

При добавлении официального стабильного релиза:
1. Проверить релиз и наличие arm64/x86_64 DMG в `ergohaven/entropy`.
2. Скачать оба файла, вычислить SHA256 и сверить digest релизных assets. Не заменять проверку `sha256 :no_check`.
3. В `Casks/entropy.rb` обновить `version` и оба `sha256`; не менять cask token, bundle или app artifact без отдельной проверки миграции.
4. Выполнить `ruby -c Casks/entropy.rb`, `ruby tests/cask_contract.rb` и CI tap.
5. Проверить обновление на Mac с прежней версией. Отдельно отметить повторные запросы Gatekeeper и сохранение нужных разрешений; успешное скачивание этого не доказывает.
6. Публиковать только проверенные изменения. Не добавлять обход защиты для устранения ошибок CI/запуска.
